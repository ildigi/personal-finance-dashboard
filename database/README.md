# database

- `seeds/` — dati iniziali in YAML: `categories.yaml` (categorie e sottocategorie, SPEC §11),
  `income_classifications.yaml` (tipologie di entrata, SPEC §12), `merchants.yaml` (merchant noti
  con alias e categoria predefinita), `rules.yaml` (regole di sistema). Applicati da
  `uv run python -m app.db.seed` (da `backend/`).
- Lo schema vive nelle migrazioni Alembic in `backend/alembic/versions/`; i modelli in
  `backend/app/models/`. Il modello dati è descritto in [SPEC §10](../docs/SPEC.md).

Database locali (PostgreSQL 18, solo `localhost`):

| DB | Uso |
|---|---|
| `finance` | dati reali |
| `finance_test` | test automatici (schema ricreato a ogni run) |

Utente applicativo: `finance_app` (nessun privilegio di amministrazione). Credenziali in `DATABASE_URL` / `TEST_DATABASE_URL` (`backend/.env`) oppure in `${DATA_DIR}/secrets/db.env`. Creazione: `docker compose up -d db` oppure `database/create-databases.sql`.

## Convenzioni dello schema

| Cosa | Regola |
|---|---|
| Chiavi primarie | `id BIGINT GENERATED BY DEFAULT AS IDENTITY` (eccezioni: `transaction_tags`, `fx_rates` con chiave composta) |
| Timestamp | `created_at`, `updated_at` `TIMESTAMPTZ` su tutte le tabelle |
| Importi | `NUMERIC(14,2)` — mai `float` (un test verifica che non esistano colonne `real`/`double`) |
| Quantità e prezzi unitari | `NUMERIC(20,8)` (azioni frazionate, prezzi con più di 2 decimali) |
| Tassi di cambio | `NUMERIC(20,10)` |
| Valute | `CHAR(3)` + `CHECK` formato ISO 4217 (`^[A-Z]{3}$`) |
| Enum | `TEXT` + `CHECK (col IN (...))`, vincolo `ck_<tabella>_<colonna>_valid` |
| Nomi dei vincoli | `pk_`, `uq_`, `fk_`, `ck_`, `ix_` generati da convenzione (stabili per Alembic) |
| Sottocategorie | FK composta `(subcategory_id, category_id)` → `subcategories(id, category_id)`: una sottocategoria non può finire sotto la categoria sbagliata |
| Ricerca testuale | indice GIN `to_tsvector('simple', description_clean)` su `transactions` |

**Cancellazioni.** I dati finanziari non spariscono in cascata: `transactions → accounts → account_sources`
sono `RESTRICT`. In cascata vanno solo i dati derivati (saldi storici di un conto, tag e override di un
movimento, snapshot di un portafoglio, log di una sorgente). I collegamenti opzionali
(coppia di trasferimento, rimborso, ricorrenza, regola, merchant) diventano `NULL`.

**Seed idempotente.** Ogni riga del seed ha un `code` stabile; il seed inserisce solo i codici mancanti e
non modifica mai righe esistenti, quindi rinomine, colori e archiviazioni fatte dall'interfaccia restano.
